# TelescopeDAQ v0.3: полное описание программы

## 1. Назначение и оборудование

TelescopeDAQ регистрирует raw waveform с **CAEN DT5740D** через USB и сохраняет
их в ROOT. Основной интерфейс версии 0.3: локальный веб-сервер FastAPI и
HTML/JavaScript в браузере. CLI и настольный Tkinter GUI остаются доступными.

Backend рассчитан на Windows x64, CAENDigitizer Library и STANDARD waveform
firmware. DPP-PHA и DPP-QDC не поддерживаются данным кодом. Модель подключённой
платы проверяется до настройки; несоответствие DT5740D вызывает ошибку.

Программно используются каналы 0..15. Это ограничение конфигурации приложения,
а не утверждение о числе входов всех вариантов семейства x740.
Параметры offset и self-trigger настраиваются группами по восемь каналов.

## 3. Архитектура

```text
Браузер -> FastAPI -> DAQService -> один caen-owner worker
                                      |
                             CAENDigitizer.read_events
                                      |
                                 Acquisition
                            /                    \
                 RootWriter, все samples     свежий preview с holdoff
                            |                    |
                          ROOT            JSON -> uPlot в браузере

ROOT Viewer -> отдельные файловые задачи -> закрытый ROOT
```

Только один рабочий поток сервиса открывает, настраивает, читает и закрывает CAEN.
HTTP-запросы не выполняют длительную регистрацию в event loop FastAPI.
Start/Connect/Scan возвращают принятие задания, результат виден в статусе и Logs.

Регистрация использует синхронную запись ROOT в том же worker. Это сохраняет
порядок событий и предсказуемое владение буферами; отдельная неблокирующая очередь
writer пока не реализована. Медленный диск может ограничивать acquisition.
Браузер не передаёт подтверждения для каждого события и не управляет циклом чтения.

Online-подписчики получают последние доступные данные. Ошибка consumer отображения
логируется и отключает этот consumer, но не прекращает запись ROOT.
Offline-задачи имеют отдельный пул исполнения; одновременно обрабатываются не
более двух операций чтения/индексации. Они не вызывают аппаратный backend, однако
могут конкурировать с записью за CPU и диск.

## 4. Жизненный цикл run

1. Загрузка и проверка YAML, создание независимого снимка конфигурации.
2. Проверка отсутствия ROOT и YAML с тем же Run ID.
3. Создание `run_NNNNNN_config.yaml`; существующий файл не заменяется.
4. Использование подключённого CAEN либо открытие нового handle.
5. Проверка модели, reset, настройка групп, длины записи и источника trigger.
6. Создание ROOT, запуск acquisition.
7. Чтение пакетов, ограничение по числу физических событий, пакетная запись.
8. Примерно раз в секунду: flush небольшого накопленного пакета и статус.
9. Остановка по лимиту, Stop, Emergency Stop или завершению сервера.
10. Остановка прибора, завершение writer и освобождение CAEN независимо друг от друга.

При ошибке открытия, чтения или записи приложение сообщает `error`, закрывает
доступные ресурсы и остаётся доступным через HTTP. Если файл уже создан,
он не удаляется автоматически. После устранения причины нужен новый Run ID.
Обрыв питания, завершение процесса через Task Manager и зависший драйвер не
эквивалентны нормальному Stop; сохранность незавершённого ROOT не гарантируется.

## 5. Режимы DAQ

### Full Monitor

Записывает все принятые waveform. Показывает Run Control, график событий за
последние 30 минут, Channels Overview и отдельную вкладку Online Waveform.
Выбор отображаемых каналов не меняет каналов записи.

Экран получает кадр не чаще `monitor.waveform_update_interval_s`.
В одном кадре показана последняя доступная waveform каждого канала.
Изображение не накладывает последовательные события друг на друга.
У длинной waveform для экрана сохраняются минимумы/максимумы блоков и конечная
точка, примерно до 2048 точек на канал; одиночный узкий пик не теряется.

### Write Only

Использует тот же acquisition и ROOT Writer.
Не вызывает waveform consumer, не строит waveform JSON и не обновляет
online-графики. Оставляет компактный статус:
Run ID, elapsed, accepted events, события за интервал, written waveforms,
размер ROOT, свободный диск, последний timestamp, ошибки CAEN.

Открытие старого ROOT остаётся разрешённым. Это осознанная пользовательская
нагрузка, а не обязательная часть Write Only.

### ROOT Viewer

Не открывает CAEN. Выбор режима запрещает Start Run, но вкладка Viewer также
доступна во время регистрации в других режимах.
Файлы выбираются из output или загружаются через браузер; upload до 512 MiB.
Для больших файлов используйте каталог output без upload.
Активный файл текущего run защищён от просмотра и скачивания.

Читаются выбранная waveform-запись и скалярная статистика. Полный массив waveform
файла в память не загружается. Сводки четырёх последних файлов кешируются по
пути, размеру и времени изменения. Метаданные читаются порциями около 8 MB.
График показывает число физических событий в 100 интервалах относительных ticks.
Это не калиброванный Hz vs seconds: единицы TriggerTimeTag отдельно не подтверждены.

## 6. Источники trigger

### Threshold

Используется ch0, порог `threshold.value_adc` в пределах 0..4095.
Это абсолютное значение ADC, не превышение относительно вычисленного baseline.
Направление импульса выбирается `channels.polarity: positive | negative`.
Включена self-trigger группы 0, её trigger mask оставляет ch0.
Остальные выбранные каналы записываются вместе с событием.

### External

TRG-IN включается через `CAEN_DGTZ_SetExtTriggerInputMode(ACQ_ONLY)`.
Self-trigger и software-trigger отключаются. `external.io_level` выбирает
NIM или TTL. После настройки читаются обратно mode и IO level; несовпадение
прерывает запуск с явной ошибкой.

Поддерживается ведущий фронт (`polarity: rising` в конфиге).
`falling` не реализован и отклоняется, а не молча игнорируется.
Требуется `save_all_enabled_channels: true`.
Для NIM название rising здесь означает настройку ведущего фронта в приложении,
а не обещание регистрации положительного перепада напряжения NIM-импульса.

Этот путь реализован и покрыт mock-тестом вызовов CAEN API.
Реальный электрический тест TRG-IN на стенде в рамках веб-миграции не выполнялся.
Перед ним необходимо проверить допустимые уровни и форму импульса по
[руководству CAEN DT5740](https://www.hep.ucl.ac.uk/pbt/wikiData/manuals/Caen/DT5740_REV12.pdf)
и документации установленного DT5740D.

### Periodic

Software trigger отправляется каждые `periodic.interval_s` по монотонным часам.
Пропущенные интервалы не создают лавину догоняющих триггеров.
Это программное расписание, не точный аппаратный генератор; задержки чтения,
записи и ОС влияют на фактические моменты срабатывания.

## 7. Что сохраняется и как считать события

В ROOT есть дерево `events`:

| Поле | Тип | Значение |
| --- | --- | --- |
| event_id | uint64 | Идентификатор физического события внутри run |
| channel | uint16 | Номер канала |
| timestamp | uint64 | Аппаратный timestamp с существующей обработкой переполнения |
| trigger_type | uint16 | Настроенный источник: 1 threshold, 2 external, 3 periodic |
| waveform | var * uint16 | Полные ADC samples |
| nwaveform | int32 | Автоматический счётчик длины от uproot |

`trigger_type` обозначает настроенный эксклюзивный источник, а не отдельно
декодированный аппаратный флаг каждого события. Старые ROOT могут содержать
историческое значение 0.

У channel-waveform одного события общий event_id. Accepted events считают
уникальные ID принятого пакета; Written waveforms считают фактически переданные
в ROOT строки. Счётчик Written может отставать до flush. После корректного
завершения при 16 каналах обычно Written = Accepted × 16.

Baseline, amplitude, charge и их гистограммы удалены по требованию пользователя.
Они не возвращены при веб-миграции. ROOT всегда содержит необработанные samples.

## 8. Скорость счёта и время

Считаются события, реально прочитанные компьютером, а не установленная частота
генератора. `monitor.rate_interval_s` задаёт окно от 0.1 до 3600 s.
График показывает количество событий в этом окне; это скользящий, а не
неперекрывающийся интервал. Частота в API: count / наблюдавшаяся длительность.
До заполнения первого окна используется фактическое время наблюдения.

Группы событий получают время чтения на компьютере. Пакетный USB readout может
давать неравномерность, особенно на малых окнах. UI опрашивает статус примерно
каждые 0.5 s, acquisition публикует его примерно раз в секунду.
Наносекундная оценка arrival rate этим интерфейсом не обеспечивается.
Аппаратные timestamp хранятся для отдельного анализа.

При шаге waveform 16 ns окно из 1024 samples = 16.384 us.
Предел конфигурации 196608 samples = 3.145728 ms, но настройки firmware и памяти
могут ограничить/округлить фактически принятую прибором длину. Сверяйте записанную
длину samples и ответ драйвера; весь диапазон на реальном приборе не проверен.

## 9. Settings и защита данных

Settings содержит Run, CAEN, Channels, Threshold, External, Periodic, Storage,
Monitor. Режим DAQ не подменяет порог, offset, длину записи или выбранные каналы.
Верхние selectors задают режим следующего запуска; фактические режимы включаются
в снимок YAML рядом с ROOT.

Проверяются типы, целочисленность, конечность чисел, допустимые диапазоны,
непустой список уникальных каналов, наличие ch0 для threshold,
поддерживаемая модель/firmware/подключение и параметры внешнего trigger.
Ошибка блокирует Save и Start. Веб-сервис не допускает output вне рабочей папки.
YAML импортируется как черновик и применяется только после Save YAML.

Запись YAML атомарная. Revision защищает от перезаписи изменений другой вкладки.
Reload перечитывает и внешние изменения YAML, если DAQ не занят.
Во время run/scan настройки блокируются на сервере, а не только в HTML.
Числовая проверка не доказывает физическую корректность уровня сигнала и не
заменяет ошибок драйвера при настройке оборудования.

`run.mode` является меткой запуска. Исторический `run.file_prefix` сохраняется
для совместимости, но имя результата по-прежнему определяется `run_id`.

## 10. Threshold Scan

Отдельное окно сканирует ch0 от нижнего до верхнего порога с заданным шагом.
Верхняя граница включается, даже если шаг не попадает в неё точно.
На каждой точке сбор идёт до времени измерения либо лимита физических событий.
Если лимит достигается раньше, counts сравниваются при разном времени экспозиции;
для анализа используйте также rate_hz из CSV.

График: X = threshold ADC, Y = accepted triggers.
Щелчок по графику выбирает ближайшую точку. Use in Settings переносит значение
в черновик; для применения требуется Save YAML.
Scan не пишет ROOT, не работает одновременно с run и закрывает CAEN после окончания.
Остановка даёт частичный результат. Закрытие окна не останавливает scan.

## 11. Ошибки, логи и ограничения

Ошибки выводятся в баннер, состояние сервиса и Logs. Аппаратные сбои не включают
DEMO автоматически. Disconnect освобождает handle.
После run/scan соединение также закрывается; следующий Start может открыть его заново.

Терминал выводит logging. HTTP access-log отключён. Периодический лог acquisition
ограничен одной записью в секунду и порогом update_every_events.
Файловый журнал ротируется: 10 MiB, пять архивов; браузер хранит 1000 строк.
ROOT и логи исключены из Git.

Emergency Stop сейчас является запросом корректной остановки, без подтверждения.
Он не убивает поток DLL, не гарантирует аппаратного отключения и не считывает
все ещё не прочитанные события из памяти прибора.

Сервер без внешней аутентификации работает только на localhost.
Проверяются Host и Origin; пути файлов ограничены рабочим каталогом.
Не используйте сервер в недоверенной сети и не запускайте несколько аппаратных
процессов: межпроцессной блокировки USB в приложении нет.

## 12. Проверка и состояние готовности

Автотесты проверяют одинаковые raw данные в двух режимах, отсутствие preview в
Write Only, много каналов на один trigger, periodic/scan, ошибки writer,
отказы отображения, валидацию, конфликт revision и защиту файлов.
Browser smoke проверяет настоящие кнопки, построенный canvas, обновление waveform,
паузу, ROOT во время acquisition, upload, scan и мобильную ширину 390 px.

Синтетические тесты не измеряют максимальную пропускную способность CAEN.
Поток 100 кГц генератора не означает способность сохранять 100 тысяч полных
многоканальных waveform в секунду: объём данных, USB, длина записи и диск
остаются ограничениями. Следующий стендовый этап: TRG-IN, длительный Write Only,
контроль потерь/переполнений и профилирование реального readout.
