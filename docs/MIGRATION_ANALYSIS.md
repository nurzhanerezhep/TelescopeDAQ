# Перенос TelescopeDAQ CLI в FastAPI + HTML

## 1. Анализ исходной реализации

Исходная цепочка: `start_run.py -> run_control.py -> Acquisition -> CAENDigitizer
-> Event -> RootWriter`. Tkinter GUI уже использовал callbacks и отдельный поток.
Поэтому аппаратный цикл сохранён, а не заменён HTTP-обработчиками.

| Исходная функция | Решение при переносе |
| --- | --- |
| CAENDigitizer ctypes и STANDARD waveform decode | Сохранены, добавлены external readback и безопасное повторное close |
| ROOT raw samples без baseline/amplitude/charge | Сохранены типы и данные; исключена перезапись существующего run |
| Общий event_id для каналов одного trigger | Сохранён; веб-счётчики различают triggers и waveform rows |
| Full Monitor / Write Only | Общий writer; preview только Full Monitor |
| Threshold ch0 и group trigger mask | Сохранены |
| Periodic software trigger | Вынесен в модуль triggers с монотонным расписанием |
| Threshold Scan | Сохранены диапазон/шаг/counts/rate; добавлено веб-окно и CSV |
| Проверка YAML | Общая функция для файла, API и предварительной проверки формы |
| Offline ROOT | Новый потоковый reader для веба; legacy viewer сохранён |
| CLI и Tk GUI | Сохранены точки входа, используют обновлённое ядро |

Политика проекта не изменилась: пишем исходные waveform, не добавляем вычисление
baseline, amplitude или charge. Технические ограничения x740/group API отражены
в Settings: нет фиктивных независимых offset для каждого канала.

## 2. Оптимизация

- Старый `ak.Array(list_of_numpy_arrays)` заменён явным ListOffsetArray с одним
  непрерывным NumPy buffer, без преобразования каждого sample на уровне Python.
- Writer сбрасывает пакет при 1024 waveform или 16 MiB; дополнительно выполняется
  flush примерно раз в секунду, чтобы медленный поток не зависал в RAM до Stop.
- Счётчик скользящего окна обновляется добавлением/вычитанием пакетов, без полного
  пересчёта суммы при каждом чтении. В логгер передаётся уже вычисленное число trigger.
- Preview ограничен у источника по времени. Передаются только последние кадры,
  длинные waveform прореживаются min/max envelope, не все прочитанные события.
- Write Only вообще не вызывает waveform consumer. Ошибка consumer не прекращает ROOT.
- Браузер повторно использует uPlot, обновляет видимую вкладку, при скрытой вкладке
  прекращает опрос; Pause display не изменяет acquisition.
- HTTP status не содержит waveform-массивов. Waveform endpoint возвращает новый
  кадр только при изменении sequence. История ограничена 1801 точкой, логи 1000 строками.
- ROOT Viewer читает скалярные ветви пакетами около 8 MB и одну выбранную waveform;
  сводки кешируются для четырёх файлов. Параллелизм offline ограничен двумя задачами.
- Периодический acquisition log ограничен 1 Hz. Файловый журнал имеет ротацию.
- Web backend не импортирует Tkinter/Matplotlib для отображения; графики строит браузер.

Нельзя обещать ускорение реальной регистрации только по тестам синтетического
источника. Запись ROOT остаётся синхронной с чтением; скорость зависит от USB,
числа каналов, samples, компрессии и диска. Аппаратный dead time и потери пока
не измеряются отдельными счётчиками. В UI нет выдуманных значений temperature,
buffer occupancy, USB error breakdown или аппаратного dead time.

Локальный замер 22.09.2026, Python 3.14, Awkward 2.13: сборка массива из 512
waveform по 1024 samples занимала 3832.642 ms старым способом и 0.625 ms новым.
Взято лучшее из трёх измерений, значения всех samples проверены на равенство,
offsets подготовлены заранее. Это только подготовка массива, без USB и диска,
не коэффициент ускорения DAQ. Воспроизведение: `python scripts/benchmark_waveform_buffers.py`.

## 3. Обработка ошибок и владение ресурсами

`DAQService` содержит единственный executor с одним владельцем CAEN. HTTP
планирует задания и возвращает статус; конкурирующие run/scan/connect получают 409.
Settings используют immutable для run снимок, revision и атомарное сохранение.
Операции cleanup изолированы; ошибка диска не мешает попытке закрыть CAEN.
Баннер и Logs получают реальные ошибки, сервер продолжает обслуживать запросы.
Исключения consumer не участвуют в успехе ROOT writer.

Файлы доступны только внутри рабочего каталога и разрешённых output-папок.
Текущий записываемый ROOT блокируется для viewer/download. Старый Run ID не
перезаписывается. При аварии исходные файлы сохраняются для ручной диагностики.

## 4. External Trigger

Схема: отключить group self-trigger и SW trigger, включить TRG-IN ACQ_ONLY,
установить NIM/TTL, прочитать назад mode/level. Фиксируется источник 2 в ROOT.
В конфиг добавлен `external.io_level`, значение по умолчанию NIM.
Неподдерживаемые falling и save_all_enabled_channels=false отвергаются явно.

Проверено тестом вызовов драйвера с mock, но не реальными электрическими
импульсами. Не следует путать ведущий фронт NIM и буквальный положительный перепад.
Стендовый тест должен проверить оба используемых уровня, каналы, samples,
завершение записи, поведение без импульсов и восстановление после ошибки.

Справочные первоисточники:

- [FastAPI: lifespan](https://fastapi.tiangolo.com/advanced/events/).
- [CAEN DT5740](https://caen.it/products/dt5740/).
- [CAEN DT5740D](https://caen.it/products/dt5740d/).
- [CAEN DT5740 User Manual, rev. 12](https://www.hep.ucl.ac.uk/pbt/wikiData/manuals/Caen/DT5740_REV12.pdf).
- Установленный `CAENDigitizer.h`: объявления Set/GetExtTriggerInputMode и Set/GetIOLevel.

## 5. Проверки и следующий стендовый этап

Автотесты: режимы записи, многоканальность, raw схема, periodic, scan, ошибки
writer/driver/display, защита конфигурации и файлов. Браузерный сценарий:
настоящий Chromium, canvas pixels, изменяющиеся waveform, pause, настройки,
просмотр ROOT параллельно acquisition, загрузка файла, Write Only, scan,
десктоп 1440 px и мобильный 390 px. Ни один тест не открывает реальный CAEN.

После программной проверки нужны реальные измерения пропускной способности,
длительный Write Only, тест TRG-IN и согласование шкалы аппаратного timestamp.
ROOT Viewer поэтому показывает сырые ticks, а live rate использует время чтения
на компьютере. Наносекундная статистика в браузере не заявляется.
